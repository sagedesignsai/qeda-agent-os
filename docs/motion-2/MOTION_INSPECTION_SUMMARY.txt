WHAT IS THE MOTION SYSTEM?
───────────────────────────────────────────────────────────────────────────────

A professional-grade 3D scene editor built with:
  • Document-driven architecture (MotionDocument as single source of truth)
  • 50+ node types (cameras, lights, geometry, procedural, data-viz, UI)
  • Timeline-based animation (keyframes, clips, tracks, easing)
  • AI copilot integration (ToolLoopAgent with 40-step budget)
  • Live R3F rendering (Three.js host, 60fps independent of React)
  • Op-based mutations (all changes serializable, validated, undoable)
  • Multi-scene composition (sequences with transitions)
  • Full undo/redo, autosave, crash recovery

ARCHITECTURE LAYERS (5-LAYER SYSTEM)
───────────────────────────────────────────────────────────────────────────────

LAYER 1: DATA MODEL
  ├─ MotionDocument (immutable, 1–5 MB)
  ├─ Scenes (1–many, independent timelines)
  ├─ Nodes (scene graph with hierarchy)
  ├─ Timeline (clips, tracks, keyframes)
  ├─ Assets (library: images, models, fonts, audio)
  └─ Metadata (schema version, output resolution)

LAYER 2: OPERATIONS SYSTEM
  ├─ 50+ op types (document, asset, scene, node, track, clip, keyframe)
  ├─ Risk classification (safe / mutating / destructive)
  ├─ Zod validation (per-op schema)
  ├─ Pure reducers (same ops → same document)
  └─ Audit trail (all changes recorded)

LAYER 3: EVALUATION ENGINE
  ├─ Deterministic frame evaluation
  ├─ Timeline sampling (keyframes → interpolated values)
  ├─ Node property application
  ├─ No side effects or randomness
  └─ Clock-independent (works at any time)

LAYER 4: RENDERING PIPELINE
  ├─ R3F host (React Three Fiber)
  ├─ Three.js scene graph
  ├─ 50+ node-type renderers
  ├─ External clock subscription
  ├─ Frame loop (60fps independent of React)
  ├─ Transform gizmo for editing
  └─ Multi-view support (cinematic + editorial)

LAYER 5: EDITOR UI
  ├─ MotionEditor (shell + layout)
  ├─ MotionViewport (live preview)
  ├─ MotionInspector (context-aware properties)
  ├─ MotionTimeline (animation editor)
  ├─ MotionScenePanel (hierarchy tree)
  ├─ MotionCopilotPanel (AI assistant)
  └─ Export dialog (render presets)

───────────────────────────────────────────────────────────────────────────────
DOCUMENT STATE MANAGEMENT
───────────────────────────────────────────────────────────────────────────────

MOTIONSTORE (Zustand-like):
  store.getDocument()             Access current MotionDocument
  store.commit(label, ops)        Apply ops (creates new document)
  store.undo() / redo()           Navigate history
  store.play() / pause()          Control playback
  store.seek(time)                Scrub to time
  store.setSelection()            Ephemeral UI selection
  store.setView()                 Timeline viewport state
  
UNDO/REDO:
  Stack of documents:             200 max (configurable)
  Same ops → same document:       Deterministic replay
  No inverse ops needed:          Documents are small, immutable
  
SUBSCRIPTIONS:
  useMotionSnapshot()             React hook, renders on doc change
  useSyncExternalStore()          React sync pattern
  No playhead updates:            Clock is external
  Frame loop independent:         R3F updates without React

───────────────────────────────────────────────────────────────────────────────
KEY DESIGN PATTERNS (17 TOTAL)
───────────────────────────────────────────────────────────────────────────────

1. Operation-based mutations     All changes are ops
2. Batch atomicity               Group related ops
3. Selection as subscription     Ephemeral state in store
4. Clock external                60fps independent of React
5. Deterministic evaluation      Same input → same output
6. Immutable updates             Never mutate directly
7. Component registration        Self-registering node types
8. Adapter layers                Motion ↔ Timeline ↔ Canvas
9. Accordion inspector           One section open
10. Risk-based approval          safe / mutating / destructive
11. Registry as source           Types in code, instances in doc
12. Hook composition             Complex state in hooks
13. Page-level shortcuts         Not component-local
14. Modifier selection           Shift/Cmd for multi-select
15. Error recovery               Autosave + crash restore
16. Render blocking              Don't render until ready
17. Streaming + approval         Agent streams, UI gates ops

QUICK START FOR DEVELOPERS
───────────────────────────────────────────────────────────────────────────────

ADD A FEATURE:
  1. Read MOTION_PATTERNS_GUIDE.md (find your pattern)
  2. Check MOTION_SYSTEM_INSPECTION.md (API details)
  3. Reference similar code in src/components/motion/ or src/lib/motion/
  4. Follow the same pattern for consistency

ADD A NODE TYPE:
  1. Create definition file (src/lib/motion/nodes/category.ts)
  2. Register in src/lib/motion/nodes/index.ts
  3. Create renderer (src/components/motion/scene/nodes/)
  4. Map renderer in getMotionThreeRenderer()
  5. Test via UI

DEBUG A BUG:
  1. Use MOTION_ARCHITECTURE_DIAGRAM.md to trace data flow
  2. Check if ops are being recorded (undo/redo)
  3. Verify evaluation is deterministic (same time → same result)
  4. Profile rendering (clock should be independent)
  5. Reference MOTION_PATTERNS_GUIDE.md for common issues
